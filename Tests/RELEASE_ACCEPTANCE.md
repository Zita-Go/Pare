# 2.8.0 历史本机候选验收

更新：2026-10-29。候选版本为 2.8.0 build 33，schema v4，尚未公开发布。

## 当前已实测

- 在 880×620pt 的隔离演示窗口里，今日页显示三条个人行动；待整理自动收起，并行区默认折叠。
- 重点卡「开始 5 分钟」即时切为「暂停＋时长」，暂停后回到开始；任务状态与列表一致。
- ⌘F 切到全局搜索并实际聚焦，可直接输入；任务与待整理均可匹配，待整理结果可导航归位。
- 时间轴紧凑/详细缩放保留任务时间与时长，紧凑布局能展示约四小时；提供「现在」入口。
- 输入明确的未来提醒后出现「已设置提醒＋时间」，待整理数量不增加；核心通知计划由自动测试覆盖。
- 多 agent 独立审查发现并修复了只读退出误报和搜索漏掉待整理的问题。
- 整合后的完整自动测试 174 项通过，覆盖数据版本保护、导入写入失败回滚、跨进程文件锁、异常退出释放、计时恢复、通知提交串行/合并/超时/重试。
- Release 构建成功，Info.plist 与签名完整性校验通过；本机已安装 2.8.0 build 33。
- 本机启动第二份同版本应用后只保留一个正式 Pare 进程；升级前后任务、历史、收件箱、想法、目标与并行状态逐字段比较一致。
- 重启识别遗留个人专注时显示补记提示，不自动将离线时长记入；本轮本机运行占用采样为 CPU 0%、RSS 约 103 MiB，该单点值不等于长期性能压测。

## 发布前保留的限制

- 本机未找到 Developer ID 签名身份；Apple 公证和独立干净环境安装仍未完成。
- 自动化拖动手势不能代替真实鼠标下的象限拖放与时间块底边调整验收。
- 未在本轮真实触发系统休眠/唤醒、浏览器注意力检测或通知横幅动作；未向外部 AI 发送真实任务。
- 退出通知等待的失败、超时及重试已自动测试；真实系统通知服务拒绝/断连场景仍未故障注入。

# 2.7.1 历史预发布验收记录

更新：2026-09-08。2.7.1 继续作为预发布版交付；自动测试、隔离界面测试和本机安装均已完成，但不把尚未完成的系统级验证描述为稳定版全量验收。

## 已验证

- 147 项自动测试通过，覆盖旧数据迁移、schema v4 持久化、时间块默认时长与缩放、冲突检测、跨日清理、并行检查点、时间安排提醒、象限迁移字段保留，以及未设置估时时入口常显。
- 象限任务和待整理内容使用带来源的类型化拖放值；目标象限分别调用任务迁移或待整理归位。拖拽源启动和目标高亮可见，右键与数字键路径继续可用。
- 「今日计划」内部提供 `清单 / 时间轴`，未增加第五个顶层工作区；880pt 紧凑窗口中时间块、当前时间线、待安排区域和并行检查点可读。
- 隔离演示数据已验证清单中的安排时间、时间轴滚动定位、时间块右键菜单、取消安排后返回待安排，以及单击任务选择开始／检查时间。
- 拖放改用 macOS 13 原生类型化拖放 API；由于当前桌面自动化的拖动手势未触发系统拖放会话，发布版同时保留单击选择时间的完整替代路径。自动化限制不冒充真实拖放已通过。
- 时间安排、截止日期和普通提醒独立保存；开始专注后清除该时间块尚未触发的开始提醒，避免正在执行时重复通知。
- 并行任务只形成检查点，不占用个人时间块；同一任务继续保持“个人专注／并行进行”互斥。
- 最终发布构建为 Pare 2.7.1（build 30）；本机更新前的 2.7.0 build 28 保存在 `/private/tmp/pare-2.7.1-quadrant-drag.qvQEuc/`。
- API 地址、模型名和密钥模式扫描无命中；发布包不包含用户任务、AI 配置或钥匙串内容。

## 仍待完成的系统级验收

- 在真实鼠标操作下再次确认象限间落点，以及待安排任务拖入时间轴、时间块改时和底边缩放；右键／数字键移动和单击安排路径已可用。
- 时间安排通知的“开始专注／延后 15 分钟／完成”动作需要等待真实通知到达后逐项验证。
- 浏览器增强检测从真实浏览器事件到通知动作的完整链路。
- 实际电脑休眠／唤醒时的计时停止与恢复提醒。
- 独立干净环境安装和跨版本升级；当前包仅为 Apple Silicon、本地 ad-hoc 签名，未使用 Developer ID 签名或 Apple 公证。
