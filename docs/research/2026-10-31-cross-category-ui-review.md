# Pare 跨领域界面与交互研究

日期：2026-10-31。对照基线：Android 0.9.2，提交 `6c2e498`。

## 结论

Pare 有明确的森林绿、暖金识别性，正文可读性也不错。下一轮应优先统一视觉层级、页面结构和反馈，让任务、想法与下一步成为主角。继续增加装饰、把所有颜色调淡，或整体缩小字号，都不能解决当前最明显的问题。

推荐方向：**温暖、清楚、有分寸的个人规划工具**。行动页面便于快速扫描，思考页面便于阅读，AI 页面便于判断和采纳。四象限、想法孵化、有限的今日容量和最小下一步继续承担产品特点。

这是调研与设计建议，不是本轮已经实施的界面改版。以下尺寸是为 Pare 提出的目标，不是从竞品图片推断出的官方规格。

## 方法与边界

- 对照14款产品，覆盖旅行、音乐/播客、阅读、健康/运动、教育、摄影/照片、金融、效率/知识工具八类。
- 结合官方截图、产品演示图、帮助文档和设计复盘。Airbnb、Flighty、Apple Music、小宇宙、Reader、Monzo、Things 的公开图已目视检查；其余以官方说明为证据，不将图片说明当作已经看过图片。
- 没有安装并登录所有竞品，不能将此称为完整实机测评。宣传合成图不能当作精确尺寸标尺；Monzo、Headspace的2023案例，以及Things官网历史素材，明确作为历史设计参考。
- Pare部分来自已验收的原生QA截图和当前代码，并由三路独立审查交叉核对。本轮没有重新测量用户真机或做新的TalkBack认证。
- 第三方图仅在临时目录作分析，没有作为Pare素材加入仓库。文中仅链接官方来源；Pare截图均为虚构资料。

## Pare当前最值得改的地方

### 1. 顶部层级过多

当前今日页首项之前有标题、两枚宽模式按钮、日期/时区、统计和分组。常规字号静态合计约230–250dp，错误和运行状态条还会额外增加。已能展示六件短标题任务，但顶部仍有明显压缩空间。

建议把日期纳入页面标题区域，模式切换成为紧凑分段控件；统计和分组降为辅助信息。时区与设备相同时不必常占一行，不同或发生切换时仍明确提示。以360×800dp、普通字号、无错误横幅为基准，首项起点目标≤180dp；这是待实测的设计目标，不强求大字号保持相同密度。

证据：[MainActivity](../../android/app/src/main/java/com/pare/app/MainActivity.kt)、[TodayOverview](../../android/app/src/main/java/com/pare/app/TodayOverview.kt)。

### 2. 控件比内容更醒目

每行完成、日历、播放分别占48dp，360dp屏幕减去外边距后，标题约只剩192dp。不能再以缩小热区解决。第一步是统一图标、降低日历等次级动作的视觉重量；时间编辑入口仍保持可发现。是否进一步合并时间显示与编辑，应先验证操作步数与误触，不能为追求干净再次藏起估时、日历入口。

主次权重建议：内容标题最高，当前重点/当前运行状态次之，时间元数据随后；导航和次级按钮不应与它们争抢。图标视觉18–22dp、实际热区至少48dp，依据[Android官方可访问性规范](https://developer.android.com/develop/ui/compose/accessibility/api-defaults)。

### 3. 同类页面还没有同一套规则

任务详情顶端返回、设备页顶端关闭、目标/偏好底部关闭；同类提交按钮混用8dp小圆角与默认胶囊。建议按“阅读/管理页、编辑页、快速操作面板、短确认”四种类型统一模板，保留草稿退出保护与保存失败反馈。不是把所有页面都改成同一个弹窗。

证据：[EditorDialog](../../android/app/src/main/java/com/pare/app/EditorDialog.kt)、[GoalsWorkspace](../../android/app/src/main/java/com/pare/app/GoalsWorkspace.kt)、[PreferencesWorkspace](../../android/app/src/main/java/com/pare/app/PreferencesWorkspace.kt)。

### 4. 颜色应更有明确职责

保留森林绿与暖金。绿用于执行和进行状态，暖金优先用于今日重点；普通导航选中可使用更克制的中性色/浅绿，并提供清楚的选中标记。现在金色同时用于重点、清单模式和时长选中，容易出现多个视觉焦点。

对现有不透明token的静态计算如下，不代表完整无障碍认证：

| 配对 | 对比度 |
| --- | ---: |
| 主文字 `#21352A` / 背景 `#F6F7F2` | 12.13:1 |
| 次文字 `#5A685E` / 白底 | 5.87:1 |
| 白字 / 主按钮 `#285E49` | 7.53:1 |
| 重点文字 `#594315` / 金底 `#F6ECD4` | 7.98:1 |
| 弱边框 `#DDE4DC` / 白底 | 1.30:1 |

正文无需整体变淡。弱边框可以用于装饰分隔，但如果它是识别控件或状态的唯一依据，就需要更强标记；不能仅凭卡片边框比值给整页判合格或失败。参考[文字对比度](https://www.w3.org/WAI/WCAG21/Understanding/contrast-minimum.html)及[非文字对比度](https://www.w3.org/WAI/WCAG21/understanding/non-text-contrast.html)。

### 5. 阅读、执行与审阅应有不同节奏

- **执行：** 首屏集中任务、最小下一步、5/15/30/60分钟和开始。通知未开时保留短提示与入口，详细提醒配置按需展开。
- **想法：** 当前探索问题、最近发现与关联行动形成阅读顺序。阶段用轻标记，不为早期想法伪造完成百分比，也不急着强迫截止日期。
- **AI：** 先给可开始的建议、投入与停止标准，再展开理由和原始记录。所有将被采纳的变更仍须清楚可见、可选择，不能为了简洁隐去实际写入范围。
- **回看：** 先给少数真实的推进事实，再展开趋势与校准。等待时长和个人投入继续分开，不采用强迫打卡的奖励结构。

证据：[ExecutionDialog](../../android/app/src/main/java/com/pare/app/ExecutionDialog.kt)、[IdeaWorkspace](../../android/app/src/main/java/com/pare/app/IdeaWorkspace.kt)、[PlanningAIViews](../../android/app/src/main/java/com/pare/app/PlanningAIViews.kt)。

### 6. 反馈统一但不过度热闹

主界面保存提示已经修复，不能再当作未解决问题。目标/偏好仍有常驻“已保存”正文，容易改变布局；建议统一到稳定的短时状态区域，错误则持续显示。完成勾选、展开、拖动落位可以增加轻量过渡，让结果容易跟踪；尊重减少动画设置，不增加延迟或循环装饰。

## 建议落地规格

| 项目 | Pare建议 |
| --- | --- |
| 字体 | 保留中文系统字体；任务标题16sp，关键时间13–14sp，长文正文16sp；屏标题按角色统一20–24sp。数字计时等宽，长标题和大字号自然增高。 |
| 间距 | 页面16dp，内容步进4/8/12/16/24dp；主要依靠对齐和分组组织内容，避免每行都成为独立大卡片。 |
| 圆角 | 复用8/12/16/24dp现有基底，分别对应小控件、分组容器、强调容器和底部面板；同类按钮不混用随机形状。 |
| 颜色 | 保留当前基础色值，先修使用角色；重点卡、普通选中、成功反馈不要全部共用同一种金色强调。 |
| 交互 | 快速录入、时长选择用轻量面板；长编辑和管理用统一页面；手势提供加速，但所有关键操作都有明确入口。 |
| 反馈 | 保存中、已保存、失败、同步中、已暂停有稳定位置和一致文案；成功短暂，错误持续，不能用动画掩盖未保存。 |

## 实施次序与验收

1. **先统一基础结构：** 今日页顶部、分段控件、图标与按钮规范、返回/关闭规则。保留现有清单和时间轴的正确行为。
2. **再打磨关键流程：** 专注开始、任务详情、想法阅读、AI审阅。每个页面明确一个首要动作，仍保留可发现的次级操作和真实状态。
3. **最后补细节：** 深色主题、稳定反馈、轻量动效、空状态；仅在合适位置增加少量品牌表达。

验证应包括普通字号首屏密度、1.6倍及更大字号、长中文标题、深浅主题、键盘、返回与草稿、保存失败、离线状态、点击热区、TalkBack和减少动画。给典型操作建立基线：记下一件事、开始5分钟、改时间、找到一个想法、理解并采纳AI变更；改版不能为了截图效果显著增加操作步骤。

不建议本轮追加新的业务功能、仪表盘编辑器、皮肤市场、强制打卡、重玻璃效果或整屏装饰。先让现有能力在一套一致、可理解的界面中工作。
