# Pare Android 与 Mac 托管同步设计

状态（2026-10-30）：Android与Mac同步开发预览已实现，Free开发云端、322项Swift测试、29项Android测试及虚构数据HTTP互通已验证。Mac正式安装未替换；Android已构建并在模拟器安装，点击验收受CUA窗口绑定限制。未开通付费，未上传真实任务，未发布正式版本。

## 产品目标

手机快速记录、查看和推进今天的任务，Mac 继续用于整理和思考。两端离线可用，同一账号联网后交换变更。保留暖感精修视觉语言，手机采用适合触摸的导航和任务列表。

首版 Android 使用 Kotlin + Jetpack Compose，本地数据库承担读取和保存；网络不阻塞记录与任务操作。Mac 保留现有 SwiftUI 客户端。业务规则和跨端JSON协议作为共同依据，不直接复用AppKit/Carbon/Combine实现。

Android 版面向符合最低系统要求的主流安卓机型；最低版本在SDK选型与真机清单确定时固定。HarmonyOS 5及以上的第三方兼容安装不能作为全面支持承诺，原生鸿蒙客户端另行适配同一同步协议。

## 托管方案与取舍

建议 Supabase Auth + Postgres + 受认证保护的事务RPC。官方提供 Swift 与 Kotlin 接入文档；可采用其HTTP API，客户端不依赖Google Play服务。Realtime只用于提示拉取，离线队列、版本冲突与数据一致性仍由Pare实现，不能把Realtime当作完整离线同步引擎。

自建服务器不符合用户已选的省维护偏好；Google服务耦合较深的方案不作为默认。国内托管平台仍可作为网络实测不合格时的替代，不把业务模型绑死在供应商SDK中。

开发先使用免费项目，未授权任何付费开通。官方当前Free档闲置一周会暂停；正式稳定服务应评估Pro及实际用量，而非承诺免费永久可用。区域须根据实际使用地的网络测试选择，不能用文档可访问推断手机同步稳定。

## 同步边界

| 数据 | 首版安排 |
|---|---|
| 待整理、任务、归档、想法、探索记录、长期目标 | 同步；任务和归档保持同一UUID，以生命周期状态区分 |
| 今日选择、排序、重点、时间块、当日投入 | 统一为按规划日期和时区标识的DayPlan，同步 |
| 已结束的专注/并行会话、卡点记录 | 随任务同步，按会话UUID去重 |
| 用户手写背景、规划偏好、明确确认的偏好 | 登录开启同步时在范围说明中列明，可同步 |
| 正在运行的个人计时器和并行计时状态 | 设备本地；不因同步在另一端自动启动或续跑 |
| 通知权限、快捷键、开机启动、注意力监测、本机提醒投递状态 | 设备本地 |
| AI服务配置、API密钥、原始请求历史、撤销快照、运行诊断 | 设备本地，不上传 |
| 旧AI摘要与反馈 | 后续明确设计范围后接入，首版不自动扩展 |

这是账号隔离、HTTPS传输的云同步设计；没有承诺服务端不可解密的端到端加密。若后续增加端到端加密，需要另行设计设备配对与密钥恢复。

## 数据与跨日规则

- 现有schema6不能整份作为云同步对象：它混合任务内容、设备状态和恢复时的副作用。
- 引入版本化同步DTO。服务端版本由独立revision标识，不能用客户端时钟或lastProgressAt判断新旧。
- DayPlan以dayKey（YYYY-MM-DD）和账号明确的IANA规划时区标识；dailyWinTaskID是单字段，避免两台设备各产生一个今日重点。
- 翻篇改为读取新一天的计划，不发送“清空所有任务的今天标记”。迁移时把当前计划放入对应日期，保留旧数据备份。
- 时间块和提醒时刻保留UTC时间；规划日期与显示时区有明确转换，跨时区设备仍读取同一计划。
- 完成/归档是任务生命周期，不以每台设备启动时间决定云中身份变化。

## 同步协议

1. 每条实体有owner、kind、id、payloadVersion、revision、deletedAt、payload。
2. 每次本地操作带operationID、deviceID、受影响实体的baseRevision和变更。内容变化和outbox必须在同一次本地持久化中成功，失败则都不确认保存。
3. Mac可先将同步元数据纳入新版本原子JSON；Android使用本地数据库事务。不能用两个无事务关联的文件分别保存任务和待同步队列。
4. 云端RPC从认证上下文获取owner，校验全部revision后整批提交，并保留幂等回执。重试丢失响应的请求不会重复创建任务。
5. 拉取游标对应可靠的提交顺序。使用每用户串行提交序号，不把普通数据库sequence直接当作安全水位。
6. 删除传播tombstone；离线设备不能把已删除的旧副本重新上传成新记录。第一版不自动压缩仍可能被离线设备需要的删除标记。
7. 远端变更通过专用原子applyRemoteChanges入口应用，保留本机计时/设置，避免回声上传；重新规划本机通知并使过期AI建议的采纳检查生效。

## 冲突、首次连接与退出

- 同一实体版本冲突保留本地、云端和共同基础副本。首版使用明确冲突提示与版本选择/保留副本，不按客户端时间静默覆盖。
- 一次AI采纳、待整理转任务、创建关联行动等多实体操作必须整批成功或整批冲突。
- 完成会话按UUID去重；actualMinutes允许手工修正，不能简单把两端数字相加。
- 首次连接先拉取并显示合并摘要。空云端不代表删除本机；已有相同UUID且内容不同必须显示冲突。
- 恢复旧备份不自动当成最新云数据推送；换账号与退出账号明确处理未同步变更，禁止跨账号复用本地队列。
- 同步显示“已同步／等待联网／正在同步／需要处理冲突”；不以按钮点击成功代替云端确认。

## 移动端与提醒

首版包含随手记、今日重点、任务/四象限、想法、专注、基础提醒、AI及本地请求历史；先跑通任务与想法的跨端闭环，再扩展复杂时间轴和跨应用注意力提示。

手机导航优先今天、整理、想法；四象限提供总览与可展开列表，避免把四个长列表压进小屏。AI在相关任务/想法旁进入，延续生成前预览、采纳和请求详情。

提醒权限、精确时间权限和设备后台限制单独处理；通知开关按设备保存。后台同步为机会性执行，打开App时立即同步；不承诺后台始终在线或所有机型秒级同步。

## 上线前验收

- 同一账号两台设备新增/修改/完成；断网修改后恢复；同改/删改冲突；丢失响应重试；账号隔离与RLS拒绝跨账号访问。
- 跨日、首次上线、旧设备离线多天后重连、旧客户端版本和备份恢复。
- 主流安卓真机的通知权限、休眠、重启、后台、省电模式；Huawei不同系统分别验证。
- API密钥/原始AI历史不进入同步负载；同步开关关闭时无内容上传。
- 云端部署与真机验证完成前，不能宣布Android版或自动同步可用。
