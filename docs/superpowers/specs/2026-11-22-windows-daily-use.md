# Step Windows：日常可用首版

用户选择：先做四象限、想法项目、今日规划、步骤历史、同账号同步、专注提醒与AI；系统级注意力检测后续补齐。默认目标Windows10/11 x64（Intel/AMD）；ARM未纳入首包。

## 产品与界面

保留白底绿色S/金球图标与Step识别色。桌面侧栏：今天、四象限、想法、目标；顶部随手记和设置。任务编辑明确区分整个任务完成与完成下一步；已完成步骤默认折叠。今天保留清单与时间安排，真实安排和提醒分开。提供托盘入口、关闭主窗后保留应用的选择、可编辑的全局随手记快捷键。

用现有账号、同步格式与payload_version=1；本地先落盘，离线修改保留，初次登录仍预览合并、由用户确认开启。AI默认关闭，需要明确发送与采纳，密钥/原始历史保留本机。

## 技术选择与取舍

选择Compose Desktop1.9.3 + Kotlin2.2.21/JDK17，复用Android纯JVM领域模型、actions、同步引擎、执行与AI协议。Windows界面和平台适配独立；暂不重写Mac，不把Android MainActivity直接搬到桌面。Tauri需重写既有状态/同步逻辑，首版风险更高，因此不选。WinUI/C#原生体验好但同样增加一套领域实现。

共享核心从现有Android源目录按明确白名单编译，不复制源码；提取被Android glue藏住的Session/HTTP adapter/纯UI投影规则，Android继续使用同一来源并回归。桌面独立Gradle工程，避免要求Windows用户安装Android SDK。

持久化采用完整SyncState的原子快照（含出站队列和游标），损坏时保护原文件/备份而不是清空。Windows DPAPI保护账号token与AI密钥；非Windows开发模式不能偷偷将密钥改成明文持久化。单实例文件锁避免两进程覆盖同库。应用运行/托盘驻留时自动同步和发送提醒；完全退出后不承诺提醒。专注重启后恢复为暂停，不把停机时间计入投入。

Mac上验证共享核心、Desktop编译、隔离数据与UI逻辑；GitHub Actions windows-2022/JDK17上构建并测试，再输出含运行时的exe安装包及可携带zip，首次无商业代码签名，明确预发布。不得把Mac构建结果当作Windows已验证。

只分发公开同步项目配置；不得提交私密模型地址、模型key、账号token、真实任务或AI原始历史。隔离fixture不连接真实账号/模型。Windows实机需要补中文输入、DPI、托盘/快捷键、通知、凭据、升级保留数据验收。没有实现的系统检测/远程计时接管/桌面小组件不显示功能入口。
