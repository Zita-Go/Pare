# Pare特色工作流：从想法到今天能推进的一步

承接[产品原则](../../product-principles.md)。用户认可0.4的基础体验，要求按Pare自己的特点详细设计并优化；本轮以安卓端串起可用闭环，沿用Mac已经存在的数据概念。

## 信息架构与关键页面

### 想法与项目

列表保留紧凑标题/阶段，并显示真实的关联行动数。点开进入工作台，而非只改一个标题：顶部是想法背景与阶段，随后是“正在探索的问题”、关联行动，以及记录/发现/决定时间线。

- 阶段：萌芽、探索、推进、暂放、归档，与Mac语义一致；不会因某个任务完成自动宣布想法完成。
- 增添探索记录只追加，不覆盖原有记录。记录有稳定UUID、种类、时间；其他端的新增记录保留。
- “拆出一个行动”要求具体标题，可填下一步/完成标准、四象限、可选加入今天和当天投入。创建任务、关联到想法、加入当日计划必须同一个本地事务和同步操作组成功。
- 行动完成后仍保留想法与记录；关联的已归档任务可回看。想法可以长期存在，任务负责具体推进。

### 今天与最小下一步

今天继续保持可扫描列表。今日重点与“下一步”承担行动引导；只有一个重点，不增加一排新的首页模式。任务详情/更多菜单提供“今天怎么推进”和“我卡住了”。

- “今天怎么推进”：选择自己推进或等待结果后检查，填写今天预计投入/检查的分钟数。任务总预估与当天投入分别显示，不把45分钟任务误改成总共5分钟。
- “我卡住了”：选择不知道下一步、任务太大、精力不足、有压力/抗拒。给出本地、可解释的引导；用户写一个具体动作与停止标准，选择5/10/15分钟或自定投入，确认后保存。
- 打开面板不记为进展、不写入卡点、不调用AI。提交时才记录卡点、更新下一步/停止标准并安排今天；不自动完成任务、不假装启动计时。
- 失败保留草稿；源任务被删除、完成或相关字段在另一端改变时不静默覆盖。

### 今日时间与并行检查

首页简报显示“自己投入 / 检查 / 尚未安排”，按共享DayPlan的实际分配计算，不能把所有任务总预估直接相加。今日未完成任务才计入；以账号规划时区和日期为准。

等待外部AI/机器/人员完成工作的任务可以安排检查时间。此处是计划语义，不代表Pare已经连接或控制那些AI，也不代表另一台设备的计时器已启动。

“我卡住了”保留任务已有的个人/检查类型；缩小动作不隐式把检查改成个人工作。需要改变类型时，由用户在“今天怎么推进”明确选择。

已有日历时间块优先参与当天统计，与Mac现有规则一致。修改这类任务的当天分钟数时同步调整该时间块时长，保留开始时刻、提醒设置和其他字段；表单必须明示这一效果。分配变化只修改本任务的DayPlan条目，不覆盖其他任务。

## 后续接入的完整设计

| 能力 | 界面与行为 | 本轮状态 |
|---|---|---|
| 短时专注 | 从已定义的下一步开始5分钟；一个个人专注计时；暂停/结束确认记录；中断恢复不虚增时长 | 设计保留，未移植计时 |
| 多任务并行 | 多个外部任务可同时进行，单独记录检查节点；不占个人专注时长；共享协调状态与本机计时分离 | 本轮先实现检查计划，运行状态另行设计迁移 |
| 温和提醒 | 仅对用户选择的下一步/检查节点提醒；可稍后、暂停；尊重系统权限、省电和安静时间 | 未接入手机通知 |
| 有前情的AI | 从当前想法/任务进入；展示将引用的背景、相关记录、目标/偏好；生成可解释建议并逐项采纳，可撤销 | 未接入手机AI，无空按钮 |
| 长期回看 | 回看问题是否有新发现、关联行动是否推进、卡点是否重复；不只统计完成数量 | 本轮展示真实记录与关联行动，自动总结后续 |

## 视觉与交互规范

延续0.4的紧凑列表和系统明暗主题，在关键行动处体现Pare的特征。页面不增加常驻宣言、装饰统计卡或与当前任务无关的选项。

| 部分 | 规格与取舍 |
|---|---|
| 字体 | 页面标题20–24sp、分组16sp、正文16sp/24sp行高、辅助与按钮13sp/20sp；长内容自然增高 |
| 控件 | 点击区域至少48dp；主按钮8dp圆角，表单/容器沿用12dp层级；颜色用于状态而非装饰 |
| 想法工作台 | 背景与阶段 → 当前问题 → 记录探索/拆出行动 → 关联行动 → 探索时间线；短操作并排展示 |
| 今天 | 普通任务保持列表密度，金色只突出今日重点；行内优先展示当天投入与下一步，总估时明确标记 |
| 按需展开 | 入口放在具体任务的更多菜单；每个面板只处理一个问题，不增加首页模式 |
| 表单 | 内容可滚动，保存与关闭固定；输入错误就地解释，保存期间阻止重复操作，失败留下草稿 |
| 长期记录 | 工作台初始分别显示20条关联行动/探索记录，可继续展开；计数反映全部记录，不删除旧内容 |
| 恢复 | 重新读取前明确确认；取消不动草稿；跨日行动草稿保留文字和稳定ID，仅在确认后更换日期基线 |

## 后续优先级与验收门槛

1. **推进可靠性。** 先接个人短时专注与外部任务运行状态。必须验证后台/重启恢复、重复暂停、跨端协调、个人时间不被外部等待虚增，再展示运行入口。
2. **手机提醒。** 从用户选定的检查节点开始，明示权限与时间；验证拒绝权限、时区变化和厂商省电策略。不能把仅保存时间当作已安排系统通知。
3. **有前情的AI。** 从某个想法/行动带入相关背景，默认只提供一个可开始的建议，参考范围和理由展开查看。生成由用户发起，采纳前可预览变化并撤销；模型密钥和原始请求不随内容同步。
4. **长期回看。** 用实际探索记录、关联行动与重复卡点发现值得回看的事项。本地轻提示不后台调用模型，不强迫用户维持统计或打卡。

这些门槛区分设计方向与已完成能力；0.5优先完成前面的想法、计划、卡点闭环。

## 数据与边界

- 复用现有idea payload：stage、entries、linkedTaskIDs、nextQuestion、nextQuestionUpdatedAt；task复用nextAction、definitionOfDone、blockerEntries；DayPlan复用task_plans.allocation的personal/check和planned_minutes。
- 所有UUID小写、时间ISO8601。未知字段、历史会话、已有链接/日历字段保留。用字段级基线防止陈旧表单覆盖新修改，追加操作和稳定ID重试不得重复。
- 本地内容与待同步队列原子保存；多实体动作同组提交。保持账号隔离、退出/暂停、撤销外部授权等现有边界。
- 运行中计时器仍属于设备本地；不能为了显示并行状态直接上传整个Mac快照。密钥和AI原始历史不进入同步。
- 不新增真实模型请求、不改云端认证、不触碰Mac正式数据。QA只用独立包与虚构资料。

## 验收闭环

新建想法 → 设探索问题/阶段 → 添加发现 → 拆出具体行动并加入今天 → 区分个人或检查投入 → 记录卡点并缩小下一步 → 完成行动 → 回到想法查看记录与关联行动仍在。跨端JSON用Mac现有解码器验证；断网保存/重试/冲突和原有密度、字体、草稿测试继续通过。
